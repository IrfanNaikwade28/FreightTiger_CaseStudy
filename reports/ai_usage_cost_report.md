## Runtime LLM usage: zero

| Metric | Value |
|---|---|
| LLM API calls in the runtime pipeline | **0** |
| Input tokens sent to an LLM | **0** |
| Output tokens generated by an LLM | **0** |

These are not estimates or rounded figures — the pipeline performs **no LLM calls at all**. Nothing in `main.py`, `src/cost_analysis.py`, `src/anomaly_detection.py`, `src/note_retriever.py`, or `src/report_generator.py` opens a network connection or invokes a model.

## What the "AI" parts actually are

The case study's intelligent behaviour (searching notes, explaining flags) is implemented with **deterministic retrieval and templated, evidence-grounded explanations**:

1. **Retrieval** — rule-based matching of each route-week against context notes by exact route scope (`Origin-Destination` or `All Routes`), effective date window parsed only from text that explicitly states one, and keyword classification of cost impact (`cost_increase` / `no_impact` / `non_increase`).
2. **Explanations** — generated from templates that quote the matched note verbatim (id, date, scope, effective window, full text) or state precisely why no note applies (wrong route, out of window, or an explicit no-impact note). Explanations cannot contain facts absent from the notes because every sentence is assembled from note fields plus fixed phrasing.
3. **Verdicts** — `flagged`, `matched_note_id`, and all numbers are computed by pure functions; LLM wording variance is structurally impossible.

This is an honest design choice, not a shortcut around instrumentation: it guarantees the guardrail requirements (no hallucinated justifications, verdict/number stability across runs) rather than merely tolerating them.

## Relation to the case study's AI bonus

The brief suggests vector search/RAG and plain-English explanations as a *bonus*, and warns that hallucinated justification scores worse than "couldn't find one." With only 10 notes, exact/rule retrieval dominates recall and is fully auditable. An optional LLM layer could later paraphrase the `reason` text at temperature 0 **without touching verdicts or numbers**; it would need to:

- be added behind a flag (off by default),
- receive only the already-validated note evidence,
- instrument every call (model, prompt/completion tokens, latency) and report measured usage against published pricing.

No such layer exists in this submission, and no token counts or costs are fabricated for one.
